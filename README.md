# Данные для HSR Chest Overlay

Этот репозиторий бесплатно раздаёт программе **HSR Chest Overlay** свежие данные о персонажах
(сборки, оценка реликвий, расчёт урона, команды) и сообщает игрокам о новых версиях программы.
Свой сервер не нужен — всё делает GitHub. **Стоимость: 0 ₽.**

## Как это работает

- Каждые 6 часов GitHub сам скачивает свежую версию [HSR Optimizer](https://github.com/fribbels/hsr-optimizer)
  (MIT), собирает из неё пакет данных (~4 МБ), подписывает его секретным ключом и публикует.
  Если в HSR Optimizer ничего не поменялось — ничего не публикуется.
- Программа у игроков раз в 6 часов (и при запуске) проверяет обновление и скачивает только изменившиеся файлы.
  Подпись проверяется: без секретного ключа подменить данные невозможно.
- Данные раздаются с трёх адресов: GitHub Pages, CDN jsDelivr и raw.githubusercontent.com.
  Если один не открывается — программа берёт следующий.
- Для публичных репозиториев GitHub Actions и GitHub Pages бесплатны. Лимит Pages — 100 ГБ трафика в месяц;
  обновление обычно весит 0,3–1,5 МБ, так что хватит и на десятки тысяч игроков.

Если ничего не настраивать, программа всё равно работает — на данных, встроенных в установщик.
Просто новые персонажи появятся только со следующей версией программы.

## Настройка (один раз, ~10 минут)

1. **Репозиторий уже есть:** `github.com/g9620432-design/HSR-CHESTOVERLAY` (публичный, Public).
   Программа ищет данные именно по этому адресу — не переименовывайте репозиторий и аккаунт.
   Если когда-нибудь всё же переименуете — сообщите, и программу пересоберут под новый адрес.
2. **Откройте его:** <https://github.com/g9620432-design/HSR-CHESTOVERLAY>.
3. **Загрузите файлы.** На странице репозитория нажмите ссылку **uploading an existing file** и
   перетащите в окно **всё содержимое этой папки** (включая папку `.github`) → **Commit changes**.
   Проверьте, что в репозитории появился файл `.github/workflows/update.yml`.
   Если его нет: **Add file → Create new file**, в поле имени введите `.github/workflows/update.yml`,
   вставьте текст этого файла из папки и нажмите **Commit changes**.
4. **Добавьте секретный ключ.** **Settings → Secrets and variables → Actions → New repository secret**.
   Name: `HSRPACK_KEY`. В поле Secret вставьте всё содержимое файла `HSRPACK_KEY.txt`
   (откройте его Блокнотом, Ctrl+A, Ctrl+C) — вместе со строками `-----BEGIN…` и `-----END…`. → **Add secret**.
   > ⚠️ Файл `HSRPACK_KEY.txt` нельзя загружать в репозиторий и никому отправлять. Храните его копию в надёжном месте.
5. **Включите GitHub Pages.** **Settings → Pages → Build and deployment → Source: GitHub Actions**.
6. **Запустите первую сборку.** Вкладка **Actions** (если GitHub спросит — нажмите
   «I understand my workflows, go ahead and enable them») → слева **Обновление данных** → **Run workflow** →
   зелёная кнопка **Run workflow**. Через 3–6 минут должна появиться зелёная галочка.
7. **Проверьте.** Откройте <https://g9620432-design.github.io/HSR-CHESTOVERLAY/manifest.json> — должен открыться текст
   со строкой `"version"`. В программе: лаунчер → **Мета** → внизу строка «Данные: …» с сегодняшней датой
   (после перезапуска программы).

Дальше ничего делать не нужно: данные обновляются сами.

## Как выпустить новую версию программы

Чтобы у игроков на главной странице лаунчера появилась кнопка «Обновить»:

1. **Releases → Draft a new release** → Choose a tag: например `v1.7.0` (Create new tag) →
   прикрепите файл `HSR-Chest-Overlay-Setup-1.7.0.exe` → **Publish release**.
2. Откройте файл `app-release.json` в репозитории → карандаш ✏️ → замените его содержимое на файл
   `app-release.json`, который прилагается к новой версии (там номер версии, ссылка и контрольная сумма) →
   **Commit changes**.
3. Через ~5 минут информация о новой версии уйдёт игрокам.

Формат `app-release.json`:

```json
{
  "version": "1.7.0",
  "url": "https://github.com/g9620432-design/HSR-CHESTOVERLAY/releases/download/v1.7.0/HSR-Chest-Overlay-Setup-1.7.0.exe",
  "sha256": "контрольная сумма установщика (можно удалить эту строку)",
  "notes": { "ru": "Коротко, что нового", "en": "What's new, in short" },
  "revoked": [],
  "shops": [
    { "name": "FunPay", "url": "https://funpay.com/lots/offer?id=...", "price": { "ru": "990 ₽ навсегда", "en": "990 RUB lifetime" } }
  ]
}
```

- `revoked` — ID утёкших ключей активации (ID показывает «Генератор ключей»), например `["5HKe8Sri"]`.
  Через несколько часов программа перестанет их принимать.
- `shops` — кнопка «Купить на FunPay» в разделе «Активация»: ссылка на лот (только `https://`) и цена
  (`price` можно не писать). Меняется без новой версии — у игроков обновится через несколько часов.
  Можно указать до 4 магазинов. Если строки `shops` нет, берётся ссылка из настроек программы.

## Если что-то не работает

- **Красный крестик в Actions** — нажмите на запуск и посмотрите, на каком шаге ошибка.
  «Не задан секрет HSRPACK_KEY» — повторите шаг 4. Ошибка на шаге «Публикация на GitHub Pages» — повторите шаг 5
  (остальные адреса при этом всё равно работают).
- **Ошибка доступа при публикации (403)** — **Settings → Actions → General → Workflow permissions →
  Read and write permissions** → Save, затем снова Run workflow.
- **GitHub прислал письмо, что расписание отключено** — вкладка Actions → **Обновление данных** →
  **Enable workflow**. Обычно сборка сама не даёт расписанию отключиться.
- Опубликовать заново принудительно: Run workflow → отметьте «Опубликовать, даже если ничего не изменилось».

## Что внутри

- `.github/workflows/update.yml` — расписание и шаги сборки.
- `hsrpack/` — сборщик пакета данных (мост к расчётному движку HSR Optimizer).
- `app-release.json` — информация о последней версии программы.
- Ветка `pack` создаётся автоматически — это опубликованный пакет, руками её не трогайте.
